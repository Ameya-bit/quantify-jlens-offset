# 0.0.1 — Verifying the machinery

**Date:** 19 Aug 2026 · **Covers steps.md Step 1** · **Commits:** `51da3ff`, `47ffdf3`, `0741e5a`, `c4da1d7`

## What this entry is about

Before measuring anything, we need to trust the measuring instrument. This
entry documents that the instrument loads correctly and behaves sensibly.

**The instrument, in plain terms.** The model (Qwen3.5-4B) processes text in
32 sequential steps, called **layers**. While it works, it carries a
scratchpad of 2,560 numbers, called the **activation** — a running summary of
"what the model is thinking here." At the very end, a translation table
called the **unembedding** (written `W_U`) turns the scratchpad into one
score per **token** (the text chunks the model reads/writes — 248,320 of
them): higher score = model wants to say that token next.

A **lens** applies that final translation table *early* — at, say, layer 12
instead of the end — to see what the model is leaning toward mid-thought.
The catch: a layer-12 scratchpad is written in "layer-12 language," and
`W_U` expects the language of layer 30 (the second-to-last step). The
**J-lens** fixes this with one translation matrix per layer, written `J_ℓ`
(a 2560×2560 grid of numbers that converts a layer-ℓ scratchpad into
layer-30 language). We use the officially released `J_ℓ` matrices, not our
own. There is also an **R-lens**: same idea, same destination, different
recipe for building the matrices. The **logit lens** is the dumb baseline:
no translation at all, scratchpad straight into `W_U`.

## Code added

- `src/lens.py` — loads the model and both lens files; one shared
  `score(h, layer, kind)` function that produces token scores from an
  activation `h`, where `kind` picks the translation: `"J"`, `"R"`, or
  `"logit"` (none). Commit `47ffdf3`.
- `src/sanity.py` — the three checks below. Prints PASS/FAIL, saves the full
  record to `results/step1_sanity.json`. Commit `47ffdf3`.
- `src/peek.py` — human fact-check tool: prints each layer's 10
  highest-scoring tokens for any prompt. Commit `c4da1d7`.

**Reproduce everything in this entry:**

```bash
.venv/bin/python -m src.sanity                                    # checks 1–3
.venv/bin/python -m src.peek "The Eiffel Tower is in the city of" # observation 4–5
```

Both are deterministic (fixed prompts, no randomness): same numbers every run.

## Check 1 — the "do nothing" anchor. PASS

Translating layer-30 language into layer-30 language should change nothing.
The "change nothing" matrix is called the **identity**, written `I`. The
released file promises `J₃₀ = I` exactly.

- **Result:** largest difference between `J₃₀` and `I` is exactly `0.0`;
  same for `R₃₀`.
- **Evidence:** `results/step1_sanity.json` → `"anchor"`; produced by
  `check_anchor` in `src/sanity.py`.
- **Why it matters:** the file is built as advertised, and anything strange
  we later observe at layer 30 cannot be the lens's fault — at layer 30 the
  lens does nothing.

## Check 2 — fancy lens ≈ dumb lens near the end. PASS

At late layers, the scratchpad is already close to layer-30 language, so the
J-lens and the logit lens should mostly agree. We compare their **top-10
overlap**: of each method's 10 highest-scoring tokens, how many are shared
(0–10)?

- **Result** (3 test prompts, last position): overlap 6–9/10 at layers
  26–29; exactly 10/10 at layer 30 for all prompts. The 10/10 is forced by
  Check 1 (`J₃₀ = I` means the two methods are literally the same
  computation there) — which doubles as an end-to-end test that our readout
  code has no bugs.
- **Evidence:** `results/step1_sanity.json` → `"agreement"`.

## Check 3 — facts appear at believable depths. PASS (2/3)

If the lens is meaningful, the model's answer to a simple fact should
surface partway through the layers, not just at the very end.

| Prompt | Expected token | First seen in J-lens top-10 |
|---|---|---|
| "The Eiffel Tower is in the city of" | ` Paris` | layer 24 |
| "The capital of Japan is" | ` Tokyo` | layer 24 |
| "The chemical symbol for gold is" | ` Au` | layer 28 (late → this row failed the "by layer 24" bar) |

All three prompts were first confirmed answerable by the model itself (its
true final answer had the expected token in its top 5). Gate required 2/3.

- **Evidence:** `results/step1_sanity.json` → `"facts"` (includes the full
  top-10 lists per layer).

## Observation 4 — the junk is already visible (this is the study's target)

Not a check — a preview. In the Eiffel prompt's per-layer top-10s, layers
16–20 are dominated by tokens like `____` and `________` — underscore-run
tokens with no connection to the text. This meaningless-but-high-scoring
material is what the literature calls **trash tokens** or **junk**, and
explaining it is the entire study.

- **Evidence:** `results/step1_sanity.json` → `"facts"` → first row →
  `"jlens_top10_by_layer"` layers 16 and 20; or see it live with the peek
  command above.

## Observation 5 — honest flag: junk is not only early

In the peek run of the same prompt, at layer 30 (where the lens does
nothing, per Check 1) the underscore tokens rank *above* ` Paris`. So junk
is not purely an early-layer artifact on this model, and whatever produces
it survives to the second-to-last layer. Step 4 will measure this properly
instead of eyeballing it.

- **Evidence:** run the peek command above; look at the `L30` row.

## One deliberate deviation from the official code

Computers store numbers precisely (**fp32**) or half-precisely (**bf16/fp16**
— half the memory, more rounding). The official readout code runs the final
translation in the model's half precision. Ours forces that one step to
fp32, because the effect we are hunting is a small, constant score boost
that aggressive rounding could smear out. Documented at the top of
`src/lens.py`.
