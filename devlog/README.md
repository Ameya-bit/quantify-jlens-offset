# Dev log

One entry per unit of verified work. Rules for every entry:

1. **Plain language.** No term is used before it is defined, either earlier
   in the entry or in a previous entry.
2. **Evidence-grounded.** Every claim cites the exact command that produced
   it, the file the output lives in (when saved), and the git commit(s) that
   contain the code. A reader should be able to re-run every number.
3. **Honest flags.** Anything surprising or inconvenient gets its own section
   at the same prominence as the good news.

`DECISIONS.md` runs alongside the numbered entries: one row per
methodological choice a reader could reasonably have made differently, with
the reason, the alternative rejected, and what would reverse it. Added when
the decision is made, not reconstructed later. Overturned decisions stay in
the table, struck through, pointing at whatever replaced them.

Numbering: `0.0.x` = setup and machinery checks. `0.x.0` = a study step
(steps.md) completed. `x.0.0` = reserved for the finished writeup.

Time tracking lives in Toggl (Ameya's side), not in this repo.
